# DESIGN.md

## 1. Структуры данных и алгоритмы

### Состояние раунда и история попыток

**`GameConfig { length: number; base: number }`** — `src/types.ts`.
Это настройки раунда: длина секрета и система счисления. Храним их одним объектом, а не двумя числами, потому что они всегда используются вместе — при генерации секрета, при проверке попытки, при сохранении рекорда. Так в функции передаётся один параметр вместо трёх. Готовый алфавит в состоянии не держим: его всегда можно построить из `base` через `createDictionary`.

**`Attempt { guess: string; bulls: number; cows: number }`** — `src/types.ts`.
Одна запись истории: введённая попытка и результат её сравнения с секретом (быки и коровы).

**История попыток — массив `Attempt[]`** — `src/game/attempts.ts`.
Новая попытка добавляется без изменения старого массива: `addAttempt` возвращает `[...history, attempt]`. Массив удобен тем, что важен порядок попыток и они только добавляются. Чтобы одна и та же попытка не попала в историю дважды, есть отдельная функция `hasAttempt` — она ищет через `.some()` без учёта регистра (это нужно для hex). Модуль работает только с данными и ничего не знает про DOM или `localStorage`.

**`GameRecord { config: GameConfig; attempts: number; time: number }`** — `src/types.ts`.
Запись в таблице рекордов. В отличие от `Attempt`, она помнит настройки раунда и итоги (число попыток и время). Настройки нужны потому, что результаты при разной длине и системе несравнимы, а порядок в таблице задают число попыток и время.

**`RecordsMap = Record<string, GameRecord[]>`** — `src/types.ts`, ключ группы — `${length}-${base}` (`src/utils/configKey.ts`).
Это словарь: у каждого набора настроек — свой список рекордов. Так лимит (топ-5) применяется отдельно к каждому набору, а не ко всем сразу. Ключ — короткая строка, её удобно и группировать, и сохранять в `localStorage`. Сортировку и обрезку до лимита внутри группы делает `addRecord`: сначала по числу попыток, при равенстве — по времени, потом `slice(0, limit)`.

**Секрет и попытка — строки, а не числа.**
Секрет может начинаться с нуля (`0123`), а число потеряло бы этот ноль. В hex цифрами служат буквы `a`–`f`. Строка решает оба случая, и сравнивать символы по позициям так проще. Hex не различает регистр, поэтому и секрет, и попытку приводим к нижнему регистру через `toLowerCase()`.

### Алгоритм `generateSecret`

`generateSecret(length, base, random = Math.random)` (`src/game/generateSecret.ts`) сначала строит список всех цифр системы — `createDictionary(base)` (для hex это `['0', …, '9', 'a', …, 'f']`). Потом `length` раз берёт случайный индекс, достаёт по нему символ и **удаляет его из списка** (`splice`) — поэтому повторов не будет. В конце символы склеиваются в строку. Главное здесь — источник случайности передаётся параметром: в тестах вместо `Math.random` подставляют свою функцию и получают предсказуемый результат.

### Алгоритм `evaluateGuess`

`evaluateGuess(secret, guess)` (`src/game/evaluateGuess.ts`) сначала приводит обе строки к нижнему регистру. Затем берёт позиции символов и через `filter` считает:

- **быков** — позиции, где символы совпали;
- **коров** — позиции, где символы не совпали, но такой символ есть в секрете (проверка `includes`).

Обычной проверки `includes` достаточно, потому что и секрет, и попытка состоят из уникальных цифр: одна цифра не может быть сразу и быком, и коровой. Всё сделано через методы массивов (`map`/`filter`), без ручных счётчиков.

### Алгоритм `countPossibleSecrets`

`countPossibleSecrets(length, base)` (`src/game/countPossibleSecrets.ts`) считает, сколько всего может быть секретов. Это число способов выбрать `length` разных цифр из `base` и расставить их по порядку: `base · (base − 1) · … · (base − length + 1)`. Ноль впереди разрешён (пример `0123`), поэтому ничего вычитать не нужно.

Считается рекурсивно:

```
countPossibleSecrets(0, base) = 1
countPossibleSecrets(length, base) = base * countPossibleSecrets(length - 1, base - 1)
```

Смысл: на первую позицию можно поставить любую из `base` цифр, а дальше остаётся та же задача, но на одну позицию меньше и на одну цифру меньше. Результат сохраняется в `Map` по ключу `${length}-${base}` (мемоизация), поэтому повторный вызов с теми же аргументами не считает заново.

## 2. Сложность

Обозначения: `n = length` (длина), `b = base` (основание). В игре `n ≤ b`.

### `generateSecret` — O(n · b)

- построение списка цифр (`createDictionary`) — O(b);
- цикл из `n` шагов; на каждом достаём случайный элемент через `splice`, а он в худшем случае сдвигает часть массива — O(b);
- склейка строки — O(n).

Итого O(n · b) по времени и O(b + n) по памяти (список цифр и результат). Так как `n ≤ b`, сверху это O(b²).

### `evaluateGuess` — O(n²)

- приведение к нижнему регистру — O(n);
- построение списка позиций — O(n);
- подсчёт быков — O(n): сравнение по индексу идёт за O(1);
- подсчёт коров — O(n²): для каждой позиции `includes` пробегает секрет целиком.

Время — O(n²) (дороже всего `includes`), память — O(n).

### `isValidGuess` — O(n · b)

- проверка длины и размера множества — O(1);
- `new Set(guess.toLowerCase())` — O(n);
- построение алфавита (`createDigitValidator`) — O(b);
- проверка каждого символа: их до `n`, и на каждый `isValidChar` ищет по алфавиту линейно — O(b) на символ.

Время — O(n · b), память — O(n + b).

### `countPossibleSecrets` — O(n) в первый раз, O(1) потом

- рекурсия — это одна цепочка вызовов от `(n, b)` до `(0, b − n)`, то есть `n + 1` вызов: O(n) по времени и O(n) по глубине стека;
- мемоизация: результат каждой пары попадает в `Map`, поэтому повторный вызов с теми же аргументами — попадание в кэш за O(1). Разные пары дают разные цепочки, так что кэш помогает именно на повторных вызовах с одинаковыми аргументами — а они и происходят при каждом открытии и изменении настроек;
- память под кэш — O(n) записей на один запрос, суммарно растёт с числом разных запрошенных пар.

## 3. Принципы чистого кода

### Имена

- функции-действия названы глаголом: `generateSecret`, `evaluateGuess`, `addAttempt`, `loadRecords`;
- булевы функции начинаются с `is`/`has`: `isValidGuess`, `hasAttempt` — по имени ясно, что вернётся `true`/`false`;
- переменные и константы говорят о смысле: `recordsLimit`, `minLength`, `maxLength`, `secret`, `history`. Имён-заглушек вроде `data`, `temp`, `list` нет.

### Функции

- каждый модуль отвечает за одно: `src/game/attempts.ts` — только за историю попыток, `src/game/countPossibleSecrets.ts` — только за подсчёт вариантов;
- маленькие утилиты тоже об одной задаче: `formatDuration`, `configKey`, `focusAfterRender`;
- у чистых функций нет побочных эффектов: они возвращают новый результат и не меняют ни аргументы, ни что-то снаружи. Все функции в `src/game/` и `src/utils/` такие, поэтому их тесты идут без браузера.

### Комментарии

В игровой логике комментариев нет: имена и структура говорят сами за себя, а пересказов кода не написано.

### DRY

- ключ конфига `${length}-${base}` вынесен в `configKey` (`src/utils/configKey.ts`) и используется и в `main.ts`, и в лидерборде;
- построение алфавита — в `createDictionary` (`src/utils/createDictionary.ts`), общее для `generateSecret` и `createDigitValidator`;
- подпись системы счисления — в `baseLabel` (`src/ui/leaderBoardView.ts`).

### KISS

В `evaluateGuess` быки и коровы считаются обычной проверкой `includes`, потому что секрет состоит из уникальных цифр. Ни `Set`, ни подсчёт мультимножеств не добавлены — код остался простым и читаемым.

### Запахи кода (code smells)

- **магические числа** — значения вынесены в `src/settings.ts`: `minLength`, `maxLength`, `recordsLimit` вместо чисел, разбросанных по коду;
- **длинные функции** — интерфейс собирается по частям (`settingsView`, `gameView`, `leaderBoardView`), а не одной большой функцией;
- **мёртвый код** — неиспользуемых функций и закомментированных блоков нет;
- **длинный список параметров** — где обработчиков несколько, они передаются одним объектом: `{ onStart, onLeaderboard }` в `settingsView`, `{ onRestart, onWin, onLeaderboard }` в `gameView`.

### Разделение логики и интерфейса

Логика, интерфейс и хранение разведены по папкам: `src/game/` и `src/utils/` — логика, `src/ui/` — интерфейс, `src/storage/recordsStorage.ts` — `localStorage`, `src/main.ts` — связывает их. Ни один файл логики не обращается к DOM.

### HTML и CSS

- разметка собирается из подходящих по семантике тегов (`h1`/`h2`, `button`, `select`, `p`), а не из одних `div`;
- классы названы по назначению, а не по внешнему виду: `settings-hint`, `game`, `leaderboard`, `table-row`, `banner-actions`;
- стиль имён классов единый по проекту: слова через дефис, модификатор через `--` (например, `table-row--head`);
- динамическая разметка создаётся через `createElement` и `textContent`, без `innerHTML`/`insertAdjacentHTML`.
